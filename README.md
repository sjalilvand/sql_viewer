# نمایشگر بکاپ MySQL (app2_backup)

برنامه‌ای با **پایتون + فلسک** که فایل بکاپ MySQL (خروجی `mysqldump` با پسوند `.sql`) را می‌خواند،
جدول‌ها و داده‌های آن را **استخراج** می‌کند و با یک **رابط فارسی** در مرورگر نمایش می‌دهد.
برای فایل‌های حجیم (چند گیگابایت) بهینه شده است: فایل به‌صورت خط‌به‌خط و استریمی خوانده می‌شود
و داده‌ها در یک دیتابیس **SQLite محلی** ذخیره می‌شود تا صفحه‌بندی و جستجو سریع باشد.

## امکانات

- استخراج استریمی فایل بکاپ (مناسب فایل ۱.۳۷ گیگابایتی — مصرف حافظه کم)
- نمایش نوار پیشرفت زنده هنگام استخراج
- **پایش خودکار بکاپ جدید:** هر فایل `.sql` جدید در پوشه `backups` (یا کنار برنامه)
  تا ۲۰ ثانیه بعد خودکار کشف و استخراج می‌شود؛ استخراج در فایل موقت انجام و فقط
  در پایان جایگزین می‌شود، پس حین به‌روزرسانی هم برنامه در دسترس می‌ماند
- فهرست جداول با تعداد ستون و ردیف
- **صفحه ساختار دیتابیس:** نمودار ER تعاملی، ارتباط کشف‌شده بین جدول‌ها و
  ساختار کامل ستون‌های همه جدول‌ها
- مشاهده هر جدول با صفحه‌بندی (۲۵/۵۰/۱۰۰/۲۰۰ ردیف) + کارت «ساختار جدول» با لینک ارتباط هر ستون
- جستجوی متنی در همه ستون‌ها
- مرتب‌سازی با کلیک روی نام ستون
- خروجی CSV (با UTF-8 BOM تا در اکسل فارسی درست باز شود)
- نمایش دستور ساخت جدول (CREATE TABLE) و تعریف نماها (View)
- حالت تاریک/روشن
- ساخت خروجی **HTML ثابت** برای همه جداول (بدون نیاز به سرور)

## پیش‌نیاز

- Python 3.8 یا جدیدتر — از [python.org](https://www.python.org/downloads/) نصب کنید
  (در هنگام نصب گزینه «Add python.exe to PATH» را تیک بزنید).
- فلسک (به‌صورت خودکار در اولین اجرا نصب می‌شود).

## دریافت پروژه از گیت‌هاب

```powershell
git clone https://github.com/sjalilvand/sql_viewer.git D:\Projects\sql_viewer
cd D:\Projects\sql_viewer
```

اگر `git` نصب نیست، یا از `winget install Git.Git` استفاده کنید یا از صفحه گیت‌هاب
دکمه **Code → Download ZIP** را بزنید و فایل را در `D:\Projects\sql_viewer` باز کنید.

## اجرای سریع (ویندوز)

**با PowerShell:**

```powershell
cd C:\path\to\sql_viewer
Set-ExecutionPolicy -Scope Process Bypass -Force
.\start.ps1
```

(اگر فایل جدیدی گرفتید:  `.\start.ps1 -SqlFile "C:\path\to\backup.sql"`)

**یا با دوبار کلیک:** روی `run.bat` دوبار کلیک کنید.

سپس در مرورگر باز کنید: **http://127.0.0.1:5000**
اگر فایل بکاپ به‌صورت خودکار پیدا نشد، در همان صفحه اول مسیر کامل فایل را وارد کنید، مثلاً:

```
D:\Projects\sql_viewer\app2_backup_202611031659.sql
```

استخراج شروع می‌شود و پس از پایان، فهرست جداول نمایش داده می‌شود.

### اجرای دستی (همه سیستم‌عامل‌ها)

```bash
pip install -r requirements.txt
python app.py --file "D:\Projects\sql_viewer\app2_backup_202611031659.sql"
```

پارامترهای اختیاری: `--port 5000` و `--host 127.0.0.1`

## سه روش تعیین فایل بکاپ

| روش | توضیح |
| --- | --- |
| پارامتر اجرا | `python app.py --file "مسیر فایل"` |
| صفحه اول برنامه | مسیر را در کادر وارد و «شروع استخراج» را بزنید |
| خودکار | اگر فایل `.sql` را کنار برنامه (یا در پوشه `backup` یا `backups`) بگذارید، بزرگ‌ترین فایل انتخاب می‌شود |

مسیر پیش‌فرض داخل `app.py` هم روی همین فایل شما تنظیم شده است
(`DEFAULT_SQL_FILE = D:\Projects\sql_viewer\app2_backup_202611031659.sql`)؛
چون فایل بکاپ کنار `app.py` قرار می‌گیرد، خودکار هم پیدا می‌شود.

## استخراج از خط فرمان (بدون اجرای مرورگر)

اگر بخواهید استخراج را یک‌بار جداگانه انجام دهید (مثلاً در کنسول سرور):

```bash
python dump_parser.py --file "مسیر فایل بکاپ.sql"
```

خروجی در `viewer_data/parsed.sqlite` ذخیره می‌شود. بعد از آن، اجرای `python app.py` بدون
تکرار استخراج مستقیم داده‌ها را نمایش می‌دهد.

## ساخت خروجی HTML ثابت

برای گرفتن یک فایل HTML مستقل از هر جدول (بدون نیاز به اجرای سرور):

```bash
python export_static.py              # حداکثر ۱۰۰۰ ردیف اول هر جدول
python export_static.py --limit 5000 --out my_export
```

خروجی در پوشه `export_html` ساخته می‌شود: `index.html` به‌همراه یک فایل HTML برای هر جدول.

    ├── status.json     وضعیت و پیشرفت استخراج
    ├── seen_backups.json  بکاپ‌هایی که قبلا استخراج شده‌اند

## نکات مربوط به فایل‌های بزرگ

- **زمان استخراج:** برای فایل ۱.۳۷ گیگابایتی معمولاً چند دقیقه طول می‌کشد (بسته به سرعت دیسک).
  نوار پیشرفت در صفحه اصلی درصد پیشرفت، جدول فعلی و تعداد ردیف‌های درج‌شده را نشان می‌دهد.
- **فضای دیسک:** دیتابیس SQLite به اندازه تقریبی حجم داده‌های متنی بکاپ فضا می‌گیرد؛ حدود
  ۱ تا ۲ گیگابایت فضای خالی کنار برنامه در نظر بگیرید.
- **داده دوباره استخراج نمی‌شود:** تا وقتی `viewer_data/parsed.sqlite` موجود است، اجرای دوباره
  برنامه مستقیماً داده‌ها را نشان می‌دهد. برای استخراج مجدد، در صفحه اصلی بعد از خطا دکمه
  «تلاش دوباره» را بزنید یا فایل `viewer_data/parsed.sqlite` را حذف کنید.
- **کدگذاری:** پیش‌فرض `utf-8` است. اگر بکاپ با کدگذاری دیگری ساخته شده (مثلاً `latin1`)،
  در `dump_parser.py` پارامتر `--encoding` را تغییر دهید:
  `python dump_parser.py --file backup.sql --encoding latin1`

## صفحه ساختار دیتابیس (جدید)

از منوی بالای صفحه روی **«ساختار دیتابیس»** کلیک کنید یا به `http://127.0.0.1:5000/schema` بروید.

این صفحه کل اسکلت دیتابیس را یکجا نشان می‌دهد:

- **شاخص‌ها:** تعداد جدول، نما، مجموع ردیف‌ها، تعداد ارتباط کشف‌شده و حجم دیتابیس
- **نمودار ER تعاملی:** هر جدول یک جعبه است؛ خط‌ها ارتباط را نشان می‌دهند
  (سر فلش = جدول والد، ابتدای خط = جدول فرزند).
  با کشیدن جابه‌جا کنید، با **Ctrl + چرخ ماوس** زوم کنید، با نگه‌داشتن ماوس روی هر جدول
  فقط ارتباط‌های همان جدول روشن می‌شود و با کلیک به داده‌های همان جدول می‌روید.
- **جدول ارتباط‌ها:** فهرست کامل «جدول فرزند ← جدول والد» با نوع کشف و درصد تطابق داده
- **ساختار همه جدول‌ها:** ستون، نوع MySQL، نوع SQLite، کلید، خالی‌پذیری، پیش‌فرض و ارتباط هر ستون

بکاپ mysqldump معمولاً FOREIGN KEY فیزیکی ندارد؛ پس ارتباط‌ها از روی **نام ستون‌ها**
کشف می‌شوند (`UserID`، `EventID`، `CityID` و…) و برای جدول‌های کوچک با **نمونه‌گیری از
داده** هم تأیید می‌شوند (نشان «تأییدشده»). در صفحه هر جدول هم کارت «ساختار جدول» همین
اطلاعات را برای همان جدول با لینک به جدول والد نشان می‌دهد.

## بکاپ جدید — به‌روزرسانی خودکار (جدید)

از این به بعد هر بکاپ جدید فقط کافی است در پوشه **`sql_viewer\backups`** کپی شود:

1. برنامه (تا ۲۰ ثانیه بعد) فایل جدید را خودکار پیدا می‌کند و استخراج را شروع می‌کند؛
   نوار پیشرفت در صفحه اصلی دیده می‌شود.
2. استخراج در فایل موقت انجام می‌شود و فقط در پایانِ موفق جایگزین دیتابیس فعلی می‌شود؛
   پس وسط کار، صفحات باز قطع نمی‌شوند.
3. در پایان، پیام سبز «بکاپ جدید به‌صورت خودکار استخراج و جایگزین شد» نمایش داده می‌شود و
   همه صفحات (جداول، ساختار، داشبورد) خودکار با داده جدید به‌روز می‌شوند.

با PowerShell:

```powershell
Copy-Item "D:\Projects\sql_viewer\app2_backup_NEW.sql" "D:\Projects\sql_viewer\backups\"
```

نکته‌ها:

- فایل‌های `.sql` کنار برنامه (همان پوشه‌ای که برنامه در آن است) هم پایش می‌شوند.
- در صفحه اصلی کارت «فایل‌های بکاپ» همه فایل‌های پیداشده را با وضعیت «جدید / استخراج‌شده»
  نشان می‌دهد و دکمه «استخراج» برای شروع دستی دارد.
- تشخیص تکراری بر اساس «نام + حجم» است؛ اگر همان نام را با محتوای جدید و حجم متفاوت بریزید،
  دوباره استخراج می‌شود. اگر برنامه هنگام رسیدن فایل جدید بسته باشد، دفعه بعد که باز شود استخراج می‌شود.

## داشبورد تحلیلی

از منوی بالای صفحه روی **«داشبورد»** کلیک کنید یا به آدرس `http://127.0.0.1:5000/dashboard` بروید.

بخش‌ها: وضعیت APIها (ApiReports) — کاربران و نشست‌ها — رزرو و ارجاع — رویدادها و تعامل — پیامک‌ها — لاگ سیستم

- همه نمودارها با تاریخ **شمسی** (ماه‌ها) و اعداد فارسی نمایش داده می‌شوند.
- زیر هر نمودار دکمه **CSV** برای دانلود همان آمار هست.
- نتیجه‌ها **۵ دقیقه کش** می‌شوند؛ با دکمه «به‌روزرسانی» محاسبه دوباره انجام می‌شود.
- تشخیص ستون‌ها (تاریخ، وضعیت، نوع و…) **خودکار** است؛ اگر ستونی نباشد، آن نمودار نمایش داده نمی‌شود و بقیه سالم می‌مانند.
- ستون `Data` (JSON) جدول ApiReports با نمونه‌گیری تحلیل می‌شود: پرتکرارترین کلیدها + درصد حضور + نمونه مقدار.

**نسخه استاتیک:** در صفحه داشبورد دکمه «نسخه استاتیک» یک فایل `dashboard.html` مستقل می‌سازد
(CSS/JS/داده همه داخل فایل) که بدون برنامه و حتی بدون اینترنت با دوبار کلیک باز می‌شود.
اجرای دستی از خط فرمان:  `python export_dashboard.py`

**توجه:** اگر به اشتباه به‌جای فایل بکاپ، یک فایل باینری (مثل خود دیتابیس) معرفی شود،
پارسر خطای «بکاپ متنی SQL نیست» می‌دهد و دیتابیس استخراج‌شده قبلی را پاک نمی‌کند.

## عیب‌یابی

| مشکل | راه‌حل |
| --- | --- |
| پنجره بلافاصله بسته می‌شود | از داخل CMD اجرا کنید تا پیام خطا را ببینید؛ معمولاً پایتون نصب نیست یا در PATH نیست |
| `فایل بکاپ پیدا نشد` | مسیر کامل فایل را در صفحه اول وارد کنید یا با `--file` بدهید |
| متن‌های فارسی خراب نمایش داده می‌شوند | کدگذاری بکاپ را با `--encoding` تنظیم کنید |
| صفحه «خطای داخلی سرور» هنگام مشاهده جدول | استخراج هنوز کامل نشده؛ تا پایان نوار پیشرفت صبر کنید |
| جستجو در جدول‌های خیلی بزرگ کند است | طبیعی است (اسکن LIKE روی همه ردیف‌ها)؛ با «ردیف در صفحه» کمتر و صفحه‌بندی کار کنید |
| نوار پیشرفت مدت زیادی سر جای خود مانده | از نسخه ۱.۱ به بعد اگر فرایند استخراج به هر دلیل متوقف شده باشد، حداکثر تا چند ثانیه بعد خود صفحه به حالت خطا می‌رود و دکمه «تلاش دوباره» می‌دهد؛ دیگر هیچ‌وقت بی‌پایان روی یک درصد نمی‌ماند. در لاگ قبلاً `PermissionError: WinError 5` دیده می‌شد که در همین نسخه برطرف شده است |
| خطاهای عجیب `is not recognized` هنگام اجرای run.bat | در نسخه‌های قدیمی فایل run.bat متن فارسی داشت که cmd خراب می‌خواند؛ run.bat فعلی فقط انگلیسی است و این مشکل ندارد |

## محدودیت‌های شناخته‌شده

- این ابزار برای «نمایش» بکاپ است؛ اجرای دستورهای تریگر، رویه و رویداد استخراج نمی‌شود و
  فقط جداول و نماها پشتیبانی می‌شوند.
- اگر ردیفی از محدودیت‌های ساختار پارسر خارج باشد (مثلاً INSERT با عبارت محاسباتی به‌جای
  مقدار ثابت)، آن ردیف نادیده گرفته شده و تعداد هشدارها در صفحه اصلی نمایش داده می‌شود.
